# Что не так с дизайном COMS — аудит

_Свод трёх итераций дизайн-совета (5 советников → анонимное перекрёстное ревью → председатель, ×3) + проверка по коду (`client/src/App.css`, `client/src/App.jsx`). Токены подтверждены grep-ом по файлам — не пересказ брифа._

---

## 1. Краткий вердикт

COMS выглядит дёшево не из-за плохого вкуса, а потому что это **дефолты, наваленные на дефолты, без системы материала, цвета и шкал**. Три «поверхности» — это плёнки белого при 4/6/8% над почти-чёрным фоном: разброс светлоты по всей шкале высоты ~2%, поэтому страница, карточка, инпут и модалка визуально лежат в одной плоскости — отсюда «плоские серые прямоугольники». Акцент `#f5d565` — это низконасыщенная горчица, которая на чёрном читается как «предупреждение/такси», а не «премиум»; при этом в бизнес-режиме акцент вообще подменяется произвольным цветом компании через JS, то есть бренд растворяется именно там, где должен доказывать легитимность. Главный рычаг: **один revertible `:root`-диф — сплошные поверхности + сигнатурная фаска-подсветка + фикс-акцент** — за полдня убирает ~70% «отталкивает», и на него уже чисто ложатся всё остальное.

---

## 2. Корневые проблемы эстетики

### 2.1. Поверхности / «прямоугольники» и глубина — ГЛАВНОЕ

**Сейчас (подтверждено):**
```css
--surface-1: rgba(255,255,255,0.04);
--surface-2: rgba(255,255,255,0.06);
--surface-3: rgba(255,255,255,0.08);
```
Глубина имитируется прозрачностью «почти ничего»: нет ни одной сплошной заливки карточки, тени почти нигде нет. Карточка, инпут, модалка и фон — один перцептивный слой. Это и есть корень «плоских прямоугольников» — проблема не в прямоугольниках, а в том, что ничто не выше и не громче соседа.

**Куда двигать — сплошные токены + сигнатурная фаска:**
```css
--s0:#0d0f12;  --s1:#15181d;  --s2:#1b1f26;  --s3:#22272f;
--edge:#2a2f38;
--elev: inset 0 1px 0 rgba(255,255,255,.06), 0 8px 24px -8px rgba(0,0,0,.7);
```
Каждая приподнятая поверхность: `background:var(--s1..s3)` + `border:1px solid var(--edge)` + `box-shadow:var(--elev)`. Верхняя внутренняя `inset`-подсветка (эффект фаски «тёплого металла») — это ownable-деталь COMS, и именно она механически убивает «плоскость». Ставить **до** цвета, типографики и motion. Осторожно с `#0d0f12` на OLED — проверить бандинг/крош теней.

### 2.2. Палитра и акцент

**Сейчас (подтверждено):** `--accent:#f5d565` / `--accent-ink:#141414`. Хуже, чем считал совет: акцент не просто меняется в бизнес-режиме — он делегирован **каждой компании** и перезаписывается через JS (`App.jsx` `root.style.setProperty('--accent', brandCompany.accent)`). То есть у бренда нет фиксированной идентичности вообще; в самый ответственный момент цвет — произвольный. Это самое разрушительное для доверия решение.

**Куда двигать:**
- Один акцент, **фиксированный во всех трёх режимах**: teal-cyan `--accent:#4dd0c4`. Рамп `#0f3d38 / #1f6b62 / #4dd0c4 / #7fe3da / #c9f5ef`. Режим — это **текстовый бейдж, а не перекраска**. Убрать `setProperty('--accent', …)` per-company как источник идентичности (максимум — второстепенная метка компании, не глобальный акцент).
- Горчицу `#f5d565` **не удалять, а понизить** до точки live/REC (`.live-dot`) — это единственная equity, которую COMS уже занимает.
- **WCAG-ловушка (проверено арифметикой):** teal `#4dd0c4` как мелкий текст на тёмном фоне ~3.9:1 — **проваливает AA**. Teal — только для заливок и крупного текста (≥3:1); для teal-текста брать тёмный шаг рампа `--accent-ink:#0f3d38` и подтверждать ≥4.5:1.

### 2.3. Типографика

**Сейчас (подтверждено):** размеры вразнос — 11/12/13/14/15/16/18/19/22/26/28/34px без единого коэффициента; веса скачут 700↔800; `.brand` = 34px/800; `.subtitle { text-transform: lowercase }` — искусственно ломает регистр русских подписей. Нет заданной body line-height.

**Куда двигать:** Inter + Inter Display для заголовков. Шкала **12/14/16/20/25/31** (ratio ~1.25), веса **500/600/700** (убрать все 800). `line-height` 1.55 body / 1.15 heading. `letter-spacing:-0.01em` на 20px+. `.brand` 34→20px. Удалить `text-transform:lowercase` у `.subtitle`.

### 2.4. Система кнопок

**Сейчас (подтверждено — это баг, а не стиль):**
```css
.ghost-btn { background: var(--surface-2); border: 1px solid var(--surface-3); }
```
Заливка 6% + рамка-волосок 8% — это **буквально рецепт `:disabled`**. Экран перед звонком складывает одну жёлтую primary поверх трёх ghost-кнопок → читается как одна живая и три мёртвые, иерархия инвертирована.

**Куда двигать — три варианта, один `.btn`, радиус 12, размеры 36/44/52:**
- **primary** — акцентный градиент `linear-gradient(180deg,#7fe3da,#4dd0c4)`, тёмный ink, `inset`-верхняя подсветка;
- **secondary** — **сплошной** `--s2` + `--edge` (чинит «выглядит выключенной»);
- **ghost** — прозрачная, только третичные действия.
Pre-call → одна teal primary CTA + понижённые secondary, а не четыре равных в стопке.

### 2.5. Радиусы и отступы

**Сейчас (подтверждено):** радиусы 6/9/10/12/14/16/18/24/999 — ничто не рифмуется. Отступы вне 4px-сетки.

**Куда двигать:** коллапс радиусов в **8/12/16 (+20 для крупных hero-поверхностей)**, удалить 6/9/10/11/14/18. Отступы — строгая **4px-сетка: 4/8/12/16/24/32**. Всё это тоже просто токены в `:root`.

### 2.6. Motion

**Сейчас:** почти нет системного motion; точечные inline-переходы. Нет focus-ring-системы, нет `prefers-reduced-motion`.

**Куда двигать:** сдержанность = премиум. Один easing, 150–200ms. Нажатие `scale(.97)`. Один focus-ring `0 0 0 3px rgba(77,208,196,.25)` @150ms. Пружина только для свитча: `cubic-bezier(.34,1.56,.64,1)` (кривая SmoothUI). Всё завернуть в `@media (prefers-reduced-motion: reduce)`.

## 3. Проблемы UX

- **Иерархия действий инвертирована.** Из-за disabled-рецепта ghost реальные действия выглядят неактивными, а единственная «живая» — предупреждающе-жёлтая. Нужен один явный CTA + понижённые второстепенные (funnel, не стопка равных).
- **Переключатели — это текст, а не свитчи.** По коду `.toggle-btn` с текстом `Вкл/Выкл` в админке и в настройках звонка (авто-камера, размытие фона). Это «дамп настроек», а не продукт. Заменить на реальный слайдер 44×26, thumb 22px, `transform .22s cubic-bezier(.34,1.56,.64,1)`. **Проверить геометрию под русские подписи** — «Вкл/Выкл» шире иконки, замена меняет ширину строки.
- **Навигация режимов.** Тройной выбор Обычный/Бизнес/Сотрудник сейчас перекрашивает всё приложение — это должно быть переключение контекста через бейдж, а не смена идентичности.
- **Плотность и белое пространство, состояния.** Нет системных loading/skeleton/empty/error. Не заданы `:focus-visible` на интерактиве.

## 4. Постранично коротко

- **Auth.** `.auth-card`: radius 24, мягкая размытая тень, стекло на почти-нечём = ничто, `.brand` 28px/800. → сплошной `--s1` + `--edge` + `--elev`, brand 20px, radius 20. Никаких анимированных градиент-hero.
- **Главный экран (pre-call).** Классический кейс «одна primary + три disabled-ghost». → funnel: teal CTA + secondary.
- **Аккаунт-модалка.** Табы `.tab-btn--active` красятся в акцент/700, внутри — mode-picker, перекрашивающий приложение. → таб-акцент teal фикс, режим = бейдж.
- **Админка.** Скопление `Вкл/Выкл` текст-тогглов + разнобой радиусов карточек-политик. → реальные свитчи, единый радиус 12/16.
- **Кабинет сотрудника.** `admin-company-dot` берёт `empCompany.accent` — снова произвольный цвет компании как акцент. → компанию показывать меткой, глобальный акцент не трогать.
- **Звонок (главный продукт, совет его почти не диагностировал).** Тёмный хром обрамляет **яркие неконтролируемые видеопотоки** (кожа, свет комнаты) — окружение это и есть само видео. → плитки radius 12, letterbox `--s0` под не-16:9 фидами, активный спикер — рамка 2px teal, контролы на тёмном scrim (**никогда tint**). Валидировать на реальных разных фидах (тон кожи, контровый/низкий свет, screen-share), а не на утверждении.

## 6. Целевое направление и Magic UI / SmoothUI / Unlumen при стеке без Tailwind

**Строить 100% на ванильном CSS. Библиотеки НЕ подключать.** Magic UI / SmoothUI / Unlumen — это стеки Tailwind + shadcn; прикручивать их к React 19 + ручному CSS = недели инфраструктуры ради эффектов, которые вручную переносятся в ~40 строк.

**Копировать как паттерн (три рецепта, ~40 строк):**
- **Unlumen** — inset-фаска глубины (`--elev` выше). Это ядро P0.
- **SmoothUI** — только кривая пружины свитча `cubic-bezier(.34,1.56,.64,1)`.
- **Magic UI** — принцип сдержанности + `scale(.97)` press. Брать дисциплину, не компоненты.

**Что не тащить:** анимированные градиент-hero, «стеклянные» template-эффекты, любые Tailwind-утилиты и shadcn-зависимости, весь runtime библиотек. Косметика поверх неисправленных «костей» — главная ловушка.

## 7. Главные ошибки, которых избегать

1. **Перекрашивать плёнки, не меняя материал.** Recolor прозрачных поверхностей ничего не даёт — сначала материал (сплошное + фаска + тень), потом цвет, в одном коммите.
2. **Оставить акцент делегированным компании / вернуть Бизнес-перекраску.** Идентичность должна уехать в первый коммит фиксированной.
3. **Взять teal как текст, не проверив контраст** (провал AA ~3.9:1). Teal = заливка/крупное; текст = тёмный шаг рампа.
4. **Подключить Magic UI/SmoothUI/Unlumen ради эффекта.** Порт рецептов, не адопт стека.
5. **Ширить P0 «пуристски» до одной только высоты** — радиусы/отступы это тоже токены, влить сразу; но при этом **не тащить в P0 свитч, in-call и hero-glow** — сначала диф на экране и подтверждение владельца, что «отталкивает» ушло.
6. **Чинить только лобби.** Звонок — где выигрывается/теряется доверие; валидировать на реальных фидах, не на утверждении.
7. **Мержить без гейта** (скриншоты + grep token-bypass + контраст). Без измерения «−70% отталкивает» — гипотеза, а teal выбран консенсусом вкуса, не реакцией владельца — пометить как гипотезу, а не факт.

## Ключевые нерешённые развилки (нужно решение владельца)

1. **Тёмная vs светлая тема.** Совет отметил: для бизнес-инструмента светлый UI часто читается легитимнее (Zoom/Meet/Teams/Stripe). Развилка не проверена — решить осознанно.
2. **Брендинг компании vs фиксированный акцент.** Совет №1: убить per-company перекраску ради идентичности COMS. Но это была намеренная фича (каждая компания выбирает цвет). Прямое противоречие — решает владелец.
3. **Акцент.** Teal `#4dd0c4` выбран консенсусом вкуса, не реакцией владельца — это гипотеза, а не факт.

_Проверенные факты кода: `client/src/App.css` — акцент `#f5d565`, поверхности .04/.06/.08, `.ghost-btn` = disabled-рецепт, `subtitle text-transform:lowercase`, `.brand` 34px/800, радиусы 6/9/10/12/14/16/18/24/999, размеры 11–34px, веса 700/800. `client/src/App.jsx` — акцент задаётся per-company через `root.style.setProperty('--accent', brandCompany.accent)`, текст-тогглы `Вкл/Выкл`._
